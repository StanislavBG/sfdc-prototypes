Unify Source Profiles

Identity resolution in Salesforce Data Cloud is the process that links data about the same person (or account) across sources into a unified profile using an identity resolution ruleset (match rules + reconciliation rules).

When you gather data from multiple sources like CRMs, marketing systems, or third-party tools, you may end up with duplicate or fragmented records for the same customer. Identity Resolution helps solve this by merging data from various sources into one complete, accurate profile for each customer or account.

Key Concepts

Source Profiles & Unified Profiles

  • Source profiles are the records from your source data streams that Data Cloud reviews during the identity resolution process to identify matching profiles.
  • Unified profiles are profiles that have been processed by identity resolution. Each unified profile is created from one or more source profiles.
  • The unified profile is made up of both the Unified Link Individual DMO and Unified Individual DMO. With the unified profile, you have access to both source data and reconciled data.

Rulesets

Rulesets allow you to configure match rules and reconciliation rules about a specific object, such as Individual. The system follows these rules to link together multiple sources of data into a unified profile.

  • Rulesets allow you to have up to 2 different Profile Unification sets per data space in a Data Cloud Org.
  • You can only have up to 2 different Rulesets for Identity Resolution per data model and data space in a single Data Cloud Org.

Match Rules

Match rules tell Data Cloud which profiles to unify during identity resolution. They're built from one or more criteria.

  • Match rules are algorithms used to determine whether two or more records represent the same customer.
  • They can be exact (e.g., matching email addresses) or fuzzy (e.g., similar names or misspellings).
  • Salesforce allows businesses to customize these rules to align with their unique data patterns and customer identification requirements.

Reconciliation Rules

For certain fields, such as first name, identity resolution must select which data from multiple matched source records is stored in the output unified profile. Data can be reconciled based on:

  • Frequency of a value
  • Recency (most recent value)
  • Source priority (based on the object it came from)

You can select reconciliation rules at the object level and field level.

Output Objects

Once rulesets are run, unified individual profiles are created, along with the following objects:

Object Description
Unified Individual The main unified profile object containing reconciled data from all matched source profiles.
Unified Contact Point Objects Individuals and businesses may have more than one valid address, phone number, or email address. Unified contact objects store information related to unified profiles. One unified profile record can be related to many unified contact points.
Unified Link Objects These objects provide a bridge between your source data and your unified profile data, so that you can always track each piece of a unified profile back to where it came from.

Mutability of Profiles

Unified profiles are mutable, which means they change to improve the accuracy of the profile. A unified profile updates as:

  • The source data changes
  • New data sources are processed
  • You make changes to the identity resolution rules

Profiles can get added or removed from the unified profile.

Implementation Steps

  1. From Data Cloud, select the Identity Resolutions tab and click New.
  2. Select Create New Ruleset and click Next.
  3. With the default Data Space selected, choose Individual from the Primary Data Model Object dropdown.
  4. Configure your match rules and reconciliation rules.
  5. Publish the ruleset.
⏱ Timing
Once published for the first time, your account creates unified profiles within 24 hours, based on the rules assigned. After the initial creation, any changes made to your rules are processed on a daily basis.

Important Notes

  • The Unified ID of a Unified Profile is not meant to be used as a Golden Record ID. The Golden Record is one of the source IDs, selected when Activation takes place.
  • If a profile has two email addresses, regardless of which version is selected to be displayed, all unique emails are still stored for each customer. Important data is not deleted.
  • Only Known Unified Profiles count towards your entitlement limit in Data Cloud.

Best Practices

  • Use rulesets to compare and test match and reconciliation rules.
  • Unified profiles are only as trustworthy as the source system data. Identify which data source has the most up-to-date information and use this as a guide for your match and reconciliation rules.
  • Add additional match rules only after you've measured match outcomes and confirmed you're improving consolidation without harming accuracy.
  • Create a "test" ruleset to experiment with Matching and Reconciliation rules and then delete this ruleset (only Known Unified Profiles count towards your entitlement limit).
  • Identity resolution quality is heavily driven by mapping, keys, and contact point completeness. If those are weak, no amount of "better match rules" will save the outcome.
  • Begin with high-confidence identifiers (party/customer IDs, stable contact points).
  • Validate unified profiles in Profile Explorer and verify you aren't over-merging.

Common Pitfalls

Pitfall Description Impact
Under-matching Identity resolution is under-built — same person split across multiple profiles Duplicates, fragmented customer view
Over-matching Identity resolution is over-built — different people combined into one profile Incorrect merged profiles, privacy issues

Either pitfall breaks segmentation, personalization, analytics, and ROI reporting.
